FOC · Fleet Operations Control Plane
PRODUCTION
FEATURED · PLATFORM

물리 서버부터 가상화·컨테이너·네트워크·CI/CD·LLM·AI Agent까지 분산 인프라의 운영 계층을 하나의 제어면으로 통합하기 위해 직접 설계·구축한 Fleet Operations Control Plane. 단순 모니터링 대시보드가 아니라 조회·실행·승인·감사·자동화를 연결해 실제 인프라를 운영하기 위한 통합 제어 시스템입니다.

INFRASTRUCTURE CONTROL

물리 서버, VMware, Docker, 스토리지, BMC/iLO/iDRAC, 원격 전원 제어와 하드웨어 센서 상태를 하나의 운영 계층에서 관리.

AI CONTROL PLANE

MCP 기반 AI Agent와 로컬 서브에이전트를 권한·세션·승인·감사 체계 안에서 운영하고, AI의 실제 인프라 접근과 실행을 통제.

LLM / MLOPS

LiteLLM 기반 다중 모델 게이트웨이와 Langfuse 관측을 연결해 요청·토큰·지연시간·비용, API Key별 예산과 모델 상태를 추적.

NETWORK & EDGE

WireGuard, Cloudflare DNS, Reverse Proxy, 인증서와 Edge Node 상태를 통합하고 서비스 경로와 네트워크 상태를 관리.

DEVOPS & AUTOMATION

Jenkins CI, 배포·릴리스·롤백, cron·systemd·Windows 예약 작업, 백그라운드 작업과 자율 루프를 통합 관리.

OBSERVABILITY & SECURITY

Zabbix·중앙 로그·Langfuse·감사 로그를 연결해 장애와 이상 징후를 탐지하고 운영자가 판단해야 할 이벤트를 한곳에 집계.

  • Agent 권한 통제 — OAuth 기반 외부 AI Agent의 권한과 세션·토큰 상태를 관리하고, 실행 권한을 읽기·쓰기·승인 필요 작업 등으로 구분
  • Human-in-the-loop — 위험도가 있는 실행 요청을 승인 대기열로 분리하고 요청자·도구·결과·결정 이력을 감사 로그로 보존
  • 실제 인프라 실행 — MCP와 로컬 서브에이전트를 통해 서버·컨테이너·배포 계층의 작업을 원격 위임·실행
  • 하드웨어 계층 관리 — HPE iLO / Dell iDRAC 계열 BMC를 통해 CPU·메모리·팬·온도·PSU·스토리지·BIOS 상태 확인
  • 컨테이너 운영 — 분산 Docker 호스트의 컨테이너 목록·로그·자원 사용량 조회와 관리 작업을 중앙화
  • CI/CD — Jenkins 작업 상태와 콘솔 로그를 통합하고 빌드·배포·릴리스·롤백 흐름을 운영 환경과 연결
  • 네트워크 운영 — WireGuard 피어, Reverse Proxy, Cloudflare 기반 DNS·도메인·인증서 상태를 통합 관리
  • 백업 — 운영 서비스 백업을 암호화된 외부 저장소와 연계하고 백업 성공 여부와 보존 상태를 확인
  • LLM Observability — 모델별 요청량·입출력 토큰·reasoning·latency와 호출 실패 데이터를 수집해 운영 상태 분석
  • FinOps — 모델별 비용과 API Key별 spend / budget을 추적해 AI 사용량을 운영 비용 관점에서도 관리
설계 원칙 — AI가 판단할 수 있는 영역과 사람이 승인해야 하는 영역을 분리하고, 실제 실행이 일어나는 모든 경로를 권한·승인·감사 가능한 제어면 안에 두었습니다.

하루·루나 · Stateful AI Agent & Memory Platform
AI SYSTEM · MEMORY R&D

Discord 환경에서 장기간 사용자와 상호작용하는 캐릭터 AI를 위해 대화 생성뿐 아니라 기억의 생성·검색·연결·평가·교정·관측까지 하나의 시스템으로 구축한 Stateful AI Agent 프로젝트. 실제 장기 운영 과정에서 축적되는 대규모 기억을 기반으로 캐릭터가 과거의 사용자·사건·관계와 자신의 경험을 지속적으로 활용할 수 있도록 설계했습니다.

  • Persistent Long-term Memory — 대화·사용자 사실·관찰·일기·자기성찰 등 서로 다른 유형의 기억을 장기 저장하고 이후 대화에서 다시 검색할 수 있는 기억 계층 구축
  • Autonomous Conversation Memory — 하루와 루나 사이에서 생성되는 자율대화를 별도의 기억 흐름으로 축적해 사용자 입력이 없는 상황에서도 캐릭터의 경험과 관계가 이어지도록 설계
  • Graph-based Memory — 기억에서 인물·개념·사건을 추출하고 관계 그래프로 연결해 단순 벡터 유사도만으로는 찾기 어려운 연관 기억을 탐색
  • Multi-channel Retrieval — semantic·temporal·entity 등 여러 검색 채널을 결합하고 기억의 유형과 상황에 따라 서로 다른 탐색 경로를 사용할 수 있도록 구성
  • Memory Clustering — 임베딩 공간에서 관련 기억을 군집화하고 군집별 키워드·캐릭터·사용자·기억 유형·연관 군집을 분석해 장기 기억의 구조를 관측
  • Recall Inspection — 실제 질문을 입력해 어떤 기억이 검색되는지 직접 재현하고 캐릭터별 검색 결과와 주변 문맥을 확인할 수 있는 회상 미리보기 도구 구현
  • Memory Curator — 잘못 분류되거나 신뢰도가 낮은 기억을 사람이 검토하고 분류·출처·identity·disposition 등의 메타데이터를 교정하는 Human-in-the-loop 관리 도구 구축
  • Human Gold Dataset — 실제 운영 기억을 사람이 직접 라벨링한 평가 데이터셋을 구축해 AI가 제안한 기억 분류와 검색 전략을 사람 기준 정답과 비교할 수 있도록 설계
  • Trust Domain & Provenance — USER_DIRECT·MODEL_GENERATED·DISTILLED·UNKNOWN_LEGACY 등 기억의 생성 출처와 신뢰 영역을 구분하고 provenance를 유지해 기억의 기원을 추적
  • Memory Isolation / ACL — 사용자·캐릭터·기억 영역별 접근 경계를 두어 검색 과정에서 다른 사용자나 격리 영역의 기억이 잘못 노출되지 않도록 ACL 검증 적용
  • Evaluation Gate — evidence 규모·provenance 다양성·그래프 집중도·UNKNOWN_LEGACY 의존도와 blind holdout 조건 등을 검사해 재실험 가능 여부를 정량적으로 판정
  • Experiment-driven Development — Recall@10, useful path rate 등 정량 지표를 기준으로 검색 구조 변경 전후를 비교하고 개선이 입증되지 않은 변경은 HOLD 처리
핵심 설계 방향 — LLM에게 모든 대화를 그대로 다시 제공하는 방식이 아니라, 기억을 독립된 데이터 계층으로 관리하고 저장 → 구조화 → 검색 → 회상 → 평가 → 사람 검증 → 재실험의 전체 수명주기를 제어할 수 있도록 구성했습니다.
